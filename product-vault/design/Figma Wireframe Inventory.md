# Srasveda Platform — Figma Wireframes v1

**Status:** editable low-fidelity structural draft — not visual design approval and not build approval.

**Figma file:** [Open the editable wireframe](https://www.figma.com/design/YITNo7Xfit8BR5FIa3hPcF)

## Purpose

This file makes the current product-vault requirements reviewable as screens before implementation. It deliberately uses neutral wireframe styling: visual direction, approved product imagery, claims copy and final components remain pending.

## File structure

The Figma Starter plan permits three pages, so the draft is organised as:

1. `00 Overview`
   - Role map: customer, doctor, MR and admin
   - Core order, fulfilment, follow-up and support flow
2. `01 Journeys — Customer MR Doctor`
   - Customer product/detail, checkout/tracking, consultation/support
   - MR today/doctor/visit and sample follow-up/outcome
   - Doctor professional home and clinic restock order
3. `02 Admin Operations & States`
   - Action centre, doctor onboarding/playbook, orders/fulfilment
   - Product/content workspace, private routing/support
   - OTP login, empty, denied, error and responsive rules

## Review sequence

1. Confirm journeys and roles are complete.
2. Add exact fields, dropdown options, validations and permissions to each frame.
3. Choose visual direction and create the approved Figma foundations/components.
4. Add clickable prototype paths and scenario coverage.
5. Mark corresponding readiness items complete only after founder review.

## Known deliberate omissions

- No approved medical/product claims, reviews, doctor endorsements or final product media.
- No payment-provider-specific UI beyond a placeholder.
- No final design tokens or component library.
- No production implementation is authorised by this wireframe.
